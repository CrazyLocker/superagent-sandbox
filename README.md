# Superagent Sandbox

## Как это работает

Superagent — агент для одного GitHub-репозитория. Он слушает события и берётся за работу, когда её просит человек с правом ставить задачи или когда это разрешает правило, записанное командой.

1. **Запрос.** Сообщение в issue или pull request становится триггером. Агент оценивает его по политике: начинать ли новую работу, продолжать текущую или остановить её.
2. **Тикет.** Принятая работа получает мандат: зафиксированные область, правила и сила запроса. Мандат не расширяется сам по себе — более широкая задача требует нового тикета.
3. **Исполнение.** Тикет передаётся отдельному воркеру. Он работает в собственном каталоге и сессии: изучает код, вносит изменения, запускает проверки и коммитит в ветку тикета.
4. **Результат.** Готовый результат возвращается в исходное обсуждение — обычно ссылкой на pull request. Панель показывает, каким тикетам нужно внимание человека: ревью, ответ или разблокировка.
5. **Решение человека.** Pull request проверяет и сливает человек. Агент не сливает изменения сам и не включает автослияние.

Агент пишет, только когда готов результат, нужно решение или работа упёрлась в блокировку, — чтобы не тратить внимание команды на промежуточный прогресс.
